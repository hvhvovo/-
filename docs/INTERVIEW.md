# 项目复盘与面试准备

项目定位：针对第三方公开预订API的自动化测试工程。不是自己开发的酒店系统，不是AI项目。

可讲的工程问题：

1. 为什么不写死预订编号？公共记录可能变动。写入测试先独立创建数据，通过返回编号串联查询，再用Fixture清理。
2. 为什么拒绝写入还要GET？403只能说明这次响应拒绝，重新读取才能检查数据是否被意外修改。
3. 为什么检查PATCH未改字段？只检查被改字段会漏掉其他字段被清空或覆盖的回归。
4. 为什么清理前核对随机firstname？公共环境可能重置并复用ID，不能盲目删除。检查与删除之间仍有时间窗口，不能保证原子归属验证。
5. 为什么17项离线不能当接口通过？它们仅验证测试辅助代码与清理行为，在线契约需另行调用服务。
6. 为什么不自动重试POST？响应丢失不代表创建失败，直接重试可能重复创建。
7. 哪些还未做？未验证数据库、负载容量、所有异常规则、独立环境隔离；GitHub CI配置未等于已在远程运行。

使用者需要完成：阅读并能修改一个用例，解释Fixture的yield/finally，结合一份报告定位失败。代码由AI辅助生成，不声称全部独立手写。

简历候选描述（仅在本人实际运行并能解释后使用）：
针对公开预订API开展接口自动化测试，使用Python、requests、pytest覆盖预订创建、查询、完整/部分更新、鉴权拒绝及删除后状态，加入筛选和有效边界值验证；以Fixture独立准备、核验和清理测试数据，输出分组HTML/JUnit报告与请求元数据，区分网络异常、接口差异及本地检查结果。

具体新增用例数量和本机结果以自己的报告为准；不得写“发现若干真实缺陷”或“提升准确率”。
